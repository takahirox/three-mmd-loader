## Changes since published 0.1.2

[PR #107 / Issue #106](https://github.com/takahirox/three-mmd-loader/pull/107)
normalizes PMD base/sphere/custom-toon and PMX base/sphere/SubTexture/custom-toon
resource names **before cache lookup, handler selection and loading**:

- Windows, POSIX and mixed separators, repeated separators and safe dot
  segments resolve to canonical URLs. Equivalent plain/escaped filenames share
  cache entries, in-flight callbacks and canonical failure diagnostics.
- Spaces and Unicode are encoded once. Escapes are decoded once and re-encoded;
  escaped literal percent names remain literal, without recursive decoding.
- Unsafe relative traversal, drive/UNC names, controls, malformed/invalid UTF-8
  escapes, encoded separators and hidden nested traversal are rejected before
  handler selection or fetching. Relative paths stay within the resource base.
- Valid absolute, protocol-relative, root-relative, data, blob and custom URLs
  retain URL semantics. This is relative-path validation, not a general URL or
  origin sandbox. Default embedded toon textures remain unchanged.
- PMD sphere classification uses normalized names while preserving base maps.
  Parsed filenames, material source metadata and original model/image bytes are
  preserved; loading/decode errors retain existing callbacks/manager behavior.

See [texture resource paths](../texture-resource-paths.md) and its
[validation record](../texture-resource-path-validation.md). This does not
establish an Android image-decoding fix; desktop Chrome is not physical-device
Android validation.

[PR #109 / Issue #108](https://github.com/takahirox/three-mmd-loader/pull/109)
documents testing/CI performance principles. It is documentation-only, with no
shipped runtime feature. No shader, IK, physics or demo visual changes are
bundled in this preparation. The 0.1.2 material composition/lighting changes,
optional pinned Bullet and classic Worker are retained features.

## Package contract and artifact audit

The root and all eight documented `.js` subpaths remain as listed in
[README](../../README.md#takahiroxthree-mmd). ESM and strict TypeScript use the
same exports; `MMDResourcePath` is an internal module, not a new public subpath.
`three ~0.186.0` is the sole peer (tested 0.186.1), and `mmd-parser ^1.1.4` is
the sole mandatory runtime dependency. TypeScript applications install matching
`@types/three@~0.186.0`. `MMDExporter` exports VPD, not PMD/PMX/VMD.

Applications initialize compatible external Ammo and expose `globalThis.Ammo`
before synchronous physics; `{ physics: false }` needs no Ammo. For the optional
included runtime, copy the entire installed `dist/vendor/bullet/` directory,
including manifest and eight licenses, to served assets. Load classic `ammo.js`,
await its factory with `locateFile: path => new URL(path, ammoURL).href`, and
assign the result to `globalThis.Ammo`. Serve the adjacent `ammo.wasm` over
HTTP(S) as `application/wasm`. There is no automatic backend download/selection.

The repository-built Ammo-compatible distribution pins unmodified official
Bullet commit `d3afe76132fc76b0f9b2359cbaef47a3766e7fbb` and Emscripten 4.0.10;
it is not an official Ammo.js release. The manifest records recipe, glue, WASM
and license SHA-256s. Tests verify those hashes and installed copies.
Preserve the classic `dist/animation/MMDPhysicsWorker.js` beside its runtime
module, or supply `workerPhysics.createWorker`. Pass the served glue URL as
`workerPhysics.ammoURL`; the binary resolves beside it. Keep initialized
main-thread Ammo for recovery. Transferables work without cross-origin
isolation; shared memory is optional. Full examples remain in README.

The [package audit](0.1.3-package.json) records every tarball file's SHA-256,
selected source hashes, pack identity and the published-baseline comparison.

## Known non-blocking limitations

Rare severe PMD physics instability remains under investigation; startup and
finite-value checks do not prove long-running stability. Native MMD pixel
parity, raw-PMX ambient mapping, native zero-power behavior and fully resolved
Gene PMX clipping remain unverified. Existing toon/shadow/color/HDR and physics
experiment limitations remain documented. Additional visual approval is not a
release gate. Resource-path normalization alone does not solve downstream image
decoding. No physical Android testing was performed.
