## Compatibility and known limitations

Public root/eight `.js` subpaths, native ESM and TypeScript imports are unchanged.
Three.js `~0.186.0` remains the sole peer (tested 0.186.1), and
`mmd-parser ^1.1.4` the sole mandatory runtime dependency. TypeScript consumers
install matching `@types/three@~0.186.0`. `MMDExporter` exports VPD only.

**Rendered brightness changes.** Authored ambient doubles compared with 0.1.3;
scene indirect ambient loses its Lambert divisor and joins the toon stage.
Existing applications with extra AmbientLight can become brighter or clip more.
One DirectionalLight represents the native-derived key light; do not add an
AmbientLight solely to represent the same native light. Optional additional
Three lights remain supported. The controlled before/after diagnostic retains
unchanged lighting/camera/models; it does not retune Examples to conceal changes.

This remains a Three linear/HDR adaptation. Native source/display color space,
pretexture saturation/quantization, exact toon/shadow behavior, zero-power
specular and pixel parity remain unverified. The derivation uses an independent
native reconstruction, not proprietary MMD source or a native binary capture.
In particular, Gene clipping can increase; this is not a verified visual
improvement. Rare severe PMD physics instability is still under investigation;
finite startup tests do not prove long-running stability. Resource-path
normalization does not prove Android image decoding. No physical Android or
native MMD testing was performed. No unrelated physics/IK features were added.
