## Runtime changes consumers receive since published 0.1.1

[PR #97](https://github.com/takahirox/three-mmd-loader/pull/97), merged as
`0d5b1b4a482b2c9f4eb7e07143fa06487251d8de`, contains the library changes:

- PMX material morph multiply factors and additive offsets accumulate
  independently, then compose once as base × product + sum. Later multiply
  morphs no longer incorrectly scale earlier additions. Direct/group weights,
  repeated targets, reset and animation retain their documented behavior.
- Texture, sphere and toon sampler controls reconstruct RGB in source color
  space using separate multiply/add controls and control-alpha interpolation.
  Control alpha no longer changes opacity or shadow classification; real
  sampled alpha, material opacity and alpha-test inputs retain their roles.
- MMD-oriented direct diffuse removes Three's Lambert `1 / pi` factor.
  Direct specular uses authored specular RGB × light × an unnormalized
  half-vector power lobe, without Three's Fresnel/normalized Phong terms.
  Zero specular stays zero; nonpositive power has an explicit constant-lobe
  policy. Toon coordinates/ramp accumulation and direct shadow attenuation
  remain on their existing paths.

See [material morphs](../material-morphs.md) and
[material shading](../material-shading.md) for independent equations, evidence,
color-space boundaries and deferred behavior. Third-party notices retain the
material/shader provenance. There are no dependency or peer upgrades.

Already shipped in **0.1.1**, and retained in 0.1.2: optional pinned Bullet
JS/WASM and eight licenses, classic Worker physics with transferable/optional
shared-memory transport and main-thread recovery, initial animation warmup,
MotionState-first kinematic synchronization, timestep/substep/damping/joint
experiments, and unified PMD/PMX physics policy. These are retained features,
not newly released features relative to the actual published baseline.

### Examples and research, outside the npm runtime

Issues #98/#100/#102 (PRs #99/#101/#103) adjust public demo lighting and
screenshots and document the measured
[Gene PMX overbrightness investigation](../gene-light-overbrightness-investigation.md).
The four PMD demos use ambient `0xAAAAAA` and directional `0xffffff`, both
at intensity 1. Gene uses `0x888888` for both lights at intensity 1. The
13-material Gene measurements distinguish HDR contributions from canvas
clipping; they do not implement a new library feature or establish native MMD
fidelity. Examples, measurements, scripts, model assets and fixtures are
excluded from the npm tarball.

## Supported consumer contract and retained assets

Use native ESM from `@takahirox/three-mmd`, or the documented subpaths:

| Subpath after `@takahirox/three-mmd/` | Named exports |
| --- | --- |
| `loaders/MMDLoader.js` | `MMDLoader` |
| `animation/MMDAnimationHelper.js` | `MMDAnimationHelper` |
| `animation/CCDIKSolver.js` | `CCDIKSolver`, `CCDIKHelper` |
| `animation/MMDPhysics.js` | `MMDPhysics` |
| `exporters/MMDExporter.js` | `MMDExporter` |
| `materials/MMDToonMaterial.js` | `MMDToonMaterial` |
| `effects/MMDOutlineEffect.js` | `MMDOutlineEffect` |
| `materials/MMDUV.js` | `mmdAdditionalUV` |

All listed exports, plus `updateMMDUVs`, are available at the root. The same
imports resolve declarations for strict TypeScript consumers. Install
`three@~0.186.0` (tested 0.186.1), and matching `@types/three@~0.186.0` for
TypeScript. The sole mandatory runtime dependency remains `mmd-parser ^1.1.4`;
import its parser APIs directly from `mmd-parser`. `MMDExporter` exports VPD
poses, not PMD/PMX models or VMD animation.

Applications initialize a compatible Ammo and assign `globalThis.Ammo` before
synchronous physics; `{ physics: false }` needs no Ammo. The library does not
download or automatically select an Ammo backend. To use the optional included
runtime, copy the whole installed `dist/vendor/bullet/` directory to served
assets, preserving `ammo.js`, `ammo.wasm`, `manifest.json` and all eight
`LICENSE.*.txt` files. Load classic `ammo.js`, await its factory with
`locateFile: path => new URL(path, ammoURL).href`, then assign the initialized
result to `globalThis.Ammo`. Serve WASM as `application/wasm` over HTTP(S).

The distribution pins unmodified official Bullet commit
`d3afe76132fc76b0f9b2359cbaef47a3766e7fbb`, built with Emscripten 4.0.10;
it is a repository-built Ammo-compatible distribution, not an official Ammo.js
release. The included manifest pins recipe, glue, WASM and license SHA-256s.
The classic Worker is `dist/animation/MMDPhysicsWorker.js`, located relative
to its runtime module. Preserve it when bundling, or supply
`workerPhysics.createWorker`. Set `workerPhysics.ammoURL` to the served glue;
WASM resolves beside that glue. Keep main-thread Ammo initialized for recovery.
Ordinary pages use transferables; shared memory requires cross-origin isolation.
See [README](../../README.md) for complete initialization and Worker examples.

## Known non-blocking limitations

Rare severe PMD physics instability remains under investigation. Short-run
finite-value and startup tests do not prove long-running stability or a fix.
Exact native MMD pixels, raw-PMX ambient mapping and native zero-power behavior
remain unverified; toon/shadow policy and host color/HDR behavior retain the
limitations in the shading evidence. Gene lighting is an Examples trial, not
a proven library cure for clipping. Subjective visual approval and additional
physics improvements are not merge gates for this release preparation.
